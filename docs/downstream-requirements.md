# 下游需求复核台账（Toolbit）

> 状态：排期已确认，未来能力尚未实现 ｜ 实现基线：`0.6.0`（2026-11-03 定版）
> ｜ 最后复核：2026-11-03
>
> 来源：下游提供的《上游依赖缺口台账》，Draft，2026-10-29，共 I-01 至 I-22。
> 原台账标题适用 `v0.6.0`，但核实环境为本库 `v0.5.0`、铜锁 8.5.0-pre1；
> 因此必须按 `0.6.0` 最终实现重新判断，不能直接把所有条目当成当前缺口。

本文记录上游复核结论及验收边界；版本归属唯一来源仍为 [roadmap.md](roadmap.md) §2，
目标 API 见 [api-reference.md](api-reference.md)。本轮只调整排期与规范，不实现未来功能。

## 2. 实现与验收边界

- **正确性优先**：I-18/I-20 同时贯通完整序列号的读写与证书吊销路径，不能只增加
  一个显示字段；I-19 保留原始扩展 DER 和 critical/OID，仍禁止签名后编辑。
- **原生能力**：SM2 点展开与 P12 重加密均通过 native → core → API；不手写替代
  密码算法，不引入第三方依赖，不自动加载 legacy provider。
- **无损改密**：保留 key/cert/CA、bag 顺序及属性，明确拒绝不能支持的容器/算法，
  不用解析后的单 key/cert Bundle 重打包冒充无损操作。显式 WithOptions 的重编码语义
  与兼容入口的无损改密分别说明。
- **互通验收**：随机签名、加密容器以双向验证/解密及结构语义比较为准，不能要求随机
  产物逐字节相等；确定性转换与原始 DER 迁移使用逐字节断言。
- **格式纠偏**：RSA 签名输出格式见 [RFC 8017 §8](https://www.rfc-editor.org/rfc/rfc8017.html#section-8)；
  默认信任路径见 [OpenSSL X509_STORE 文档](https://docs.openssl.org/3.0/man3/X509_STORE_add_cert/)。

## 3. 维护约定

1. 本库实际交付后，按 API 及运行时铜锁版本逐条复核，再由下游关闭原台账条目和恢复
   契约；“已排期”不能算“已修复”。本表保留处置记录，不覆盖下游原附件。
2. 未来功能仅在路线图/API 的规划段登记，实际交付时更新双语 CHANGELOG；
   纯文档调整不新增条目，未发布版本既有条目中的排期引用应保持一致。
3. 新增需求沿用可追溯编号和最小复现；历史 `docs/issues/` 报告保持原样。
