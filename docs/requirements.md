## 1. 确定交付的未完成需求

本轮对照 CLI、官方 SDK 固定提交与本库源码复核；以下是确定值得交付的范围，
不表示已经实现。版本、依赖和门禁统一见 [路线图 §2](roadmap.md#2-分版本范围)，
目标公开面见 [API 清单](api-reference.md) 的 🧭 项。

| 编号 | 需求与价值 | 当前缺口 | 验收边界 |
|---|---|---|---|
| I-34 | SSHKDF / PKCS12KDF：补齐标准协议派生原语 | 两版 CLI 均可枚举，本库 Derive 尚无参数映射；PKCS#12 容器内部派生不等于公开 KDF | 独立标准向量与 CLI 对拍，验证 SSH 类型字节/session ID 与 P12 diversifier、口令字符编码、空/缺失口令及输出长度；不扩成 SSH 协议栈 |
| I-35 | EC/SM2 公钥压缩与未压缩导出：支持标准公钥编码互通与存储 | 缺公开点形式选项；SM2 压缩密文 C1 输入是另一能力 | 复用 asym 密钥、SPKI PEM/DER，不改变旧默认；点合法性、编码往返、CLI 互通、源对象不变；不承诺 hybrid 输出、任意曲线扩容或压缩密文输出 |
| I-36 | 配置式 CRL 签发与应用级组合：减少易错的手工编排 | CRLBuilder、证书/CSR 签发和 Store 已有，仍需收敛 Options、按名非对称密钥生成和组合入口 | 复用原语、完整序列号与错误路径，保留调用方信任/授权职责，不持久化 CA 数据库；破坏性变化给迁移说明 |
| I-37 | CMS：标准签验、信封与 DigestedData 互通 | 已有 PKCS#7 基础流程，但无 CMS_* 绑定与独立工作流 | 签验及加解密 CLI 双向互通；附带/分离内容、全部签名者与证书信任；摘要封装/验证不当作身份认证，篡改失败不返回成功内容 |
| I-38 | PQC / KEM：为后量子迁移提供可操作而非仅枚举的能力 | 0.13.0 已实现 ML-DSA / SLH-DSA、ML-KEM 密钥生命周期与 TLS 1.3 后量子组，原生限制见路线图 | ML-DSA 三档、SLH-DSA 12 变体、ML-KEM 三档与原生 KEM 路径；区分独立 KEM 和 TLS 组，覆盖参数错配、篡改、编码、资源释放与适用混合组实际握手 |
| I-39 | RFC 3161 时间戳：提供标准化签名时间证明的封装 | 尚无 ts 包及 TS_* 绑定 | 请求/响应、HTTP、imprint/nonce/policy、一致性与 TSA 签名/证书用途/信任/时间验证；解析成功不等于验证通过；不附带 TSA 运营服务 |

## 2. 暂缓需求与重开条件

以下有潜在价值，但暂未具备足够场景、互通约定或验证条件；不承诺版本。
明确拒绝的历史条目不再复制到本文，见 [路线图 §4](roadmap.md#4-明确不做--暂缓)。

| 编号 | 候选 | 暂缓理由与重开条件 |
|---|---|---|
| I-05 | 标准混合加密（HPKE / JWE）与 ECIES 互通 | 不自造 ECIES 容器；HPKE 与 JWE 是不同协议，需明确接收方、算法套件/模式及格式。8.5.0 安装头文件有 OSSL_HPKE 接口，但未做操作验证；确定互通对象和向量后分别立项，不把已有 JWK 当作 JWE |
| I-40 | 通过 BIO 支持任意 net.Conn | 当前 fd 后端只支持 TCP；代理包装连接、net.Pipe、隧道等场景有价值，但涉及双向 I/O、取消、关闭、内存和回调模型。具备具体使用场景后设计独立后端，验证无 fd、半关闭、deadline、背压与竞态 |
| I-41 | 数据库化 CA 工作流 | 内存签发已有；serial/index.txt、文件锁、事务、审计和吊销权限属于状态管理。明确持久化接口、并发及恢复要求后独立设计，不并入 CRL 便利入口 |
| I-42 | provider 隔离、属性查询与非文件/硬件 URI 加载 | 本地多对象加载已有，完整 OSSL_STORE、PKCS#11/硬件、provider/property 尚无对象和生命周期设计。需可用设备/测试 provider、认证回调、线程安全与句柄归属约定；不能通过公开 ENGINE 或自动加载 legacy 兜底 |
| I-43 | STARTTLS、外部 PSK、0-RTT、主动重协商 | 分别需要应用协议升级、PSK 身份/密钥管理、重放策略或协议状态约定。按明确应用场景分别评估，不作为会话恢复的默认附属能力 |
| I-44 | RSA 自定义公钥指数与多素数生成 | 官方有自定义指数、CLI 有更多参数，本库默认 65537 满足一般用法。仅在具体存量系统互通与参数约束明确时新增受限 Options，不提供任意 pkeyopt 透传 |
| I-45 | ASN.1 通用生成 / CLI 配置语言 | DER viewer 已有，标准库 encoding/asn1 能覆盖许多构造需求；需明确结构/格式及标准库不能满足的场景后评估，不复刻 genconf DSL |
| I-46 | KRB5KDF | 原生可枚举，但尚无 Kerberos 互通对象与测试参数需求。明确协议场景、算法参数和独立向量后单独补充，不因同族接口就扩大本轮范围 |
| I-47 | S/MIME 邮件封装 | CMS 只解决密码学容器，不等于 MIME、邮件规范化与附件处理。CMS 交付后按实际邮件互通样本评估；不在 CMS 版本隐含承诺 |
| I-48 | 混合证书/CRL 的 PKCS#7 容器构建与原生对象保留 | Build(certs)、FromCRL(crls) 与各自提取已有，不应重复生成 API；若需同一容器同时装多证书/CRL或保留更多对象，先给互通样本及顺序/属性要求，再设计 Bundle 入口 |

## 3. SM2DH 密钥确认的原生限制

`0.8.0` 已交付显式参数的 SM2DH 派生（静态/临时密钥、双方 ID、角色、长度，SM3）。
GB/T 32918.3 的确认消息生成、对端校验及失败后禁用密钥为独立需求：固定铜锁 8.5.0
provider 的 derive 接口仅输出派生密钥，未暴露确认值，因此延期至原生支持，不承诺版本。
调用方仍须认证静态公钥，不能把双方各自完成派生当作身份认证或密钥确认。
