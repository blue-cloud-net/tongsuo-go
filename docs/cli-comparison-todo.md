## 1. 确定交付

版本归属只在 [路线图 §2](roadmap.md#2-分版本范围) 维护；下表按需求编号导航，
不再复制一套 Phase 或版本号。目标公开形态在 [api-reference.md](api-reference.md) 标为 🧭。

| 需求 | 确定范围 | 关闭条件 |
|---|---|---|
| I-31 | 会话缓存、DER/PEM 导入导出、状态读取、票据控制与轮换 | 实际恢复、TLS 1.3 握手后票据、过期与跨身份隔离均验收 |
| I-29 | HTTP/1.1 集成、OCSP stapling 与连接状态 | 客户端/服务端集成、有效/无效 staple 与适用协议矩阵通过 |
| I-38 | ML-DSA / SLH-DSA、ML-KEM、原生 KEM 与适用的 PQC/混合 TLS 组 | 密钥生成/编码、签验/封装、篡改失败与实际协商通过 |
| I-37 | CMS 签验、信封及 DigestedData | CMS CLI 双向互通，不用 PKCS#7 冒充 CMS；摘要校验不等于身份认证 |
| I-39 | RFC 3161 时间戳请求/响应、验证及 HTTP | nonce/imprint/policy 与 TSA 身份、链/时间校验和错误路径通过 |
| I-34 | SSHKDF / PKCS12KDF | 独立向量、参数边界、口令编码及 CLI 对拍通过，不扩成 SSH 协议栈 |
| I-35 | EC/SM2 公钥压缩与未压缩导出 | 标准编码往返、CLI 互通、源对象不变与非法点拒绝 |
| I-36 | CRL 配置式签发、应用级组合及公开面收敛 | 复用已有原语，迁移说明和回归齐全，不接管 CA 数据库 |

## 2. 暂缓与不做

待确认需求为 I-05、I-40–I-48，以及 SM2DH 密钥确认。用途、限制和重开条件统一见
[需求台账](requirements.md)，不在此预生成函数名。
明确不做的范围统一见 [路线图 §4](roadmap.md#4-明确不做--暂缓)。

旧清单中的 version/info/errstr、MAC、EC 参数、PEM/形态工具、本地多对象加载、
PKCS#7 基础流程、SNI/ALPN/认证及诊断均已交付，不再列为未来待办。

## 3. 维护规则

1. 先核对源码，不能从旧文档的 ❌ 或 `[ ]` 推断功能尚未实现。
2. 有明确标准/互通对象、测试条件和 SDK 职责的条目才进入路线图；其余保留需求条件。
3. 实际交付才关闭需求并更新双语 CHANGELOG；纯规划与本次文档重写不新增 CHANGELOG 条目。
4. 不按输入源、编码和文件路径机械生成大量同义函数，优先复用 meta.Source/Sink/Format。
